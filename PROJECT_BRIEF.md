# Game1 — первоначальная инструкция проекта

Документ фиксирует цели, варианты игры, стек, публикацию и монетизацию.
Это стартовая карта: конкретный жанр и движок выбираем отдельно после обсуждения.

---

## 1. Цель проекта

1. Сделать **небольшую игру для Android** (один разработчик / небольшой объём).
2. **Выложить** игру в магазин(ы) приложений.
3. Встроить **рекламу** и получать доход.
4. Оформлять доход как **самозанятый** (НПД в РФ).

Критерии успеха первой версии (MVP):

- игра запускается на Android 8+ (или выше, по требованиям выбранного SDK рекламы);
- понятная механика за 10–30 секунд;
- сессия 1–5 минут;
- есть хотя бы один формат рекламы (banner / interstitial / rewarded);
- игра опубликована в Google Play (или альтернативном сторе, если Play недоступен на старте).

## 2. Популярные форматы небольших игр для телефонов (2025–2026)

Рынок делится так:

| Сегмент | Загрузки | Деньги | Сложность для соло |
|--------|----------|--------|--------------------|
| Hyper-casual | очень высокие | низкие–средние (в основном реклама) | низкая–средняя |
| Hybrid-casual | высокие | лучше, чем чистый hyper | средняя |
| Casual (puzzle / sim) | высокие | средние (реклама + мягкие покупки) | средняя |
| Midcore (шутеры, стратегии) | средние | высокие | высокая (не для первого проекта) |

Для **первой игры соло** разумнее целиться в **hyper / hybrid-casual** или простой **casual puzzle**: быстрее сделать, проще монетизировать рекламой.

### 2.1. Варианты жанров (подходят под «небольшую игру»)

#### A. Головоломки (Puzzle) — сильный выбор для старта

Примеры механик:

- блок-пазлы / match / merge;
- сортировка цветов / труб / шариков (sort puzzle);
- плитки / mahjong / «убери пары»;
- логика: найди отличие, мини-судоку, nonogram.

Плюсы: стабильный спрос, хорошо работают rewarded-реклама и уровни.  
Минусы: много конкурентов, нужен контент (паки уровней).

#### B. Runner / shoot’em up «бежишь и стреляешь» (Arcade / Action)

Примеры механик:

- endless runner: бежишь вперёд, уворачиваешься, собираешь монеты;
- top-down / side: бежишь, враги набегают, ты стреляешь;
- twin-stick lite: джойстик движения + автострельба;
- «wave survival»: волны врагов, апгрейды между волнами.

Плюсы: зрелищно, понятный hook, хорошо смотрится в рекламных креативах.  
Минусы: нужен баланс сложности, ощущение «сочности» (отдача оружия, эффекты), иначе бросают быстро.

#### C. Hyper-casual / .io-лайк

- дыра/пожиратель (Hole.io-стиль);
- змейка / рост шара;
- «собери толпу» / bridge race / stack;
- кликеры с одной кнопкой + простая цель.

Плюсы: быстрый прототип, много установок при удачном креативе.  
Минусы: удержание слабое; чистый hyper-casual без мета-прокачки сейчас слабее по деньгам.

#### D. Hybrid-casual (рекомендуемый «золотой» путь)

Простая core-механика + лёгкая мета:

- уровни / волны → монеты → апгрейды оружия / скинов / базы;
- короткая партия + «база/лагерь» между партиями;
- ежедневные награды, простые цели.

Пример: «бежишь и стреляешь» + апгрейд оружия между забегами.  
Или: головоломка + коллекция и бустеры.

#### E. Симуляторы / idle-lite

- тихие offline-игры, мини-ферма, «готовь еду», парковка, уборка;
- idle: тап / автодоход + апгрейды.

Плюсы: длинные сессии у части аудитории, реклама между циклами.  
Минусы: арт и UX должны быть аккуратными, иначе выглядит дешево.

#### F. Что лучше **не** брать первым проектом

- онлайн-мультиплеер, MMO, большой open world;
- полноценный battle royale / AAA-шутер;
- сложная 4X-стратегия с LiveOps «как у студии».

### 3.3. Что делать дальше (после утверждения)

Порядок работ:

1. **Поставить Unity Hub + Unity 6 LTS (или актуальный LTS)** с модулем **Android Build Support** (SDK/NDK/OpenJDK — галочки в Hub).
2. **Создать 2D-проект** `Nestglow` в этом репозитории (папка вроде `Nestglow/` или корень — лучше подпапка `game/`).
3. **Собрать вертикальный срез:** сетка 6×6 → drag → merge → спавн за энергию → победа/поражение → 1–2 тестовых уровня.
4. **Прогнать на телефоне** (USB debug APK) или хотя бы в редакторе на ПК.
5. Потом: мета (меню, 5 уровней), заглушки рекламы, стор-ассеты.

Сейчас ты на шаге **1–2**. Код прототипа начинаем, когда редактор установлен и пустой Unity-проект лежит в репо.

### 3.1. Название и сеттинг

### 3.2. Прототип механики (MVP)

**Поле:** сетка **6×6**. Каждая клетка пустая или занята одним предметом.

**Предметы (ранги 1 → 8):**

1. Искра  
2. Светлячок  
3. Огонёк  
4. Лампа  
5. Фонарь  
6. Маяк  
7. Созвездие  
8. Гнездо света *(макс. ранг в прототипе)*

**Основное действие:** зажал предмет → перетащил на **другой такой же ранг** → оба исчезают, на целевой клетке появляется **ранг + 1**.  
Перетаскивание на пустую клетку = просто перемещение.  
На занятую клетку другого ранга = ход запрещён (предмет возвращается).

**Появление новых предметов:**

- кнопка **«Достать свет»** тратит 1 энергию и спавнит в случайную пустую клетку предмет ранга **1** (с шансом ~15% — ранг **2**);
- энергия: старт уровня **N** единиц (для прототипа: 20); пустая энергия = нельзя спавнить, но можно ещё мержить то, что есть.

**Цель уровня (победа):** например «создай **2 фонаря** (ранг 5)» или «создай **1 маяк** (ранг 6)».  
Прогресс: счётчик цели на HUD.

**Поражение:** нет пустых клеток **и** нет ни одной возможной пары для merge (и энергии на спавн тоже 0 — либо сразу при забитом поле без ходов).

**Минимальный игровой цикл прототипа:**

```
меню → уровень 1 → таскай/мержи/спавнь → победа или поражение → рестарт / следующий уровень
```

**Контент прототипа (вертикальный срез):**

- 5 уровней с растущей целью (ранг 4 → ранг 6);
- простые цветные круги/спрайты по рангам (арт можно заменить позже);
- звук merge + лёгкий pop-эффект;
- без рекламы на этом этапе (слоты под interstitial после уровня и rewarded «+5 энергии» заложить в UI, но заглушкой).

**Что сознательно не делаем в первом прототипе:** сюжет, база-хаб, ивенты, онлайн, IAP, сложные бустеры, процедурная генерация на сотни уровней.

**Почему такая механика:** один экран, понятно за 10 секунд, хорошо масштабируется уровнями, удобно вешать rewarded («энергия / подсказка»), визуально читается в сторе и в коротких роликах.

## 4. На чём разрабатывать (движки и системы)

### 4.1. Unity (C#) — основной кандидат

**Да, Unity — нормальный и популярный выбор для Android-игр.**

Плюсы:

- огромная база туториалов, ассетов, плагинов;
- официальный **Google Mobile Ads (AdMob) Unity Plugin**;
- 2D и 3D, удобно для runner/shooter и puzzle;
- сборка APK/AAB под Google Play из коробки.

Минусы:

- редактор тяжёлый, лицензия Unity Runtime Fee / условия нужно сверять актуальные;
- для очень маленьких 2D-проектов может быть «избыточен».

Подходит, если хочешь экшен, эффекты, потом iOS, магазин ассетов.

### 4.2. Godot 4 (GDScript / C#) — сильная альтернатива

Плюсы:

- бесплатный, лёгкий, открытый код;
- отлично для 2D puzzle / простых аркад;
- есть плагины AdMob (community).

Минусы:

- меньше готовых ассетов и «корпоративных» гайдов;
- реклама/сторы чуть больше ручной возни, чем в Unity.

Подходит, если хочешь минимальные затраты и 2D.

### 4.3. Другие варианты (когда уместны)

| Стек | Когда брать |
|------|-------------|
| **Unreal** | почти никогда для маленькой Android-казуалки (тяжело) |
| **Native Android (Kotlin + Canvas/OpenGL)** или **Jetpack Compose + игровой цикл** | если уже сильный Android-разработчик и игра очень простая |
| **Flutter + Flame** | если уже знаешь Flutter; для игр экосистема слабее Unity/Godot |
| **Construct / Buildbox / GDevelop** | быстрые прототипы hyper-casual, меньше контроля и «серьёзности» пайплайна |
| **Defold** | хорош для 2D, менее мейнстрим |

### 4.4. Рекомендация для Game1

**Выбрано: Unity + C# + 2D** (план Personal). Godot оставлен как запасной вариант, не используется в текущем MVP.

## 5. Стек технологий (ориентир под Unity + Android + реклама)

### 5.1. Разработка игры

- **Движок:** Unity (LTS-версия)
- **Язык:** C#
- **Платформа:** Android (минимум API по требованиям AdMob, сейчас ориентир API 23+)
- **Ввод:** тач (тап, свайп, виртуальный джойстик)
- **Арт:** собственные спрайты / бесплатные пакеты / itch.io / Unity Asset Store (с проверкой лицензии)
- **Звук:** короткие SFX + простой loop
- **Контроль версий:** Git (этот репозиторий)
- **Сборка:** Android App Bundle (`.aab`) для Google Play

### 5.2. Монетизация рекламой

- **AdMob** (Google Mobile Ads) — основной SDK
- Форматы:
  - **Banner** — постоянно / на меню (мало мешает, мало денег);
  - **Interstitial** — между уровнями / после смерти (основной доход);
  - **Rewarded** — «посмотри рекламу → продолжить / подсказка / x2 монет» (лучший UX + хороший eCPM);
- Опционально позже: **Mediation** (Unity Ads, AppLovin, ironSource и т.д.) через AdMob mediation.

### 5.3. Аналитика и качество

- **Firebase Analytics** / Unity Analytics (по желанию)
- **Crashlytics** — краши
- **Google Play Console** — статистика установок, ANR, отзывы

### 5.4. Аккаунты и юридическое (РФ, самозанятый)

- аккаунт **Google Play Console** (разовый регистрационный взнос **US$25**, без ежегодного продления);
- аккаунт **AdMob** (привязка к Google-аккаунту);
- статус **самозанятого** (НПД) в приложении «Мой налог»;
- для выплат AdMob: заполнить налоговый профиль / платежные данные в кабинете Google (условия и пороги выплат смотреть в актуальной справке AdMob);
- **политика конфиденциальности** (Privacy Policy) — обязательна для стора и рекламы (можно хостинг на GitHub Pages / простой сайт);
- соблюдение правил Google Play по рекламе, детям (если аудитория kids — отдельные жёсткие ограничения; для старта лучше **не** детская аудитория).

> Важно: этот файл — не налоговая/юридическая консультация. Ставки НПД, валюта выплат, комиссии магазина и требования AdMob нужно сверить по официальным источникам на момент релиза.

### 5.5. Опционально позже

- внутриигровые покупки (убрать рекламу / скины) через Google Play Billing;
- Remote Config / A-B тесты сложности и частоты рекламы;
- iOS / App Store (отдельный аккаунт Apple Developer).

## 6. Куда выложить игру

### 6.1. Основной канал

- **Google Play** — главный магазин для Android, нужен для нормального охвата и удобной связки с AdMob.

Шаги в общем виде:

1. Создать игру (product) в Play Console.
2. Подготовить store listing: иконка, скриншоты, описание, категория, возрастной рейтинг (IARC).
3. Загрузить `.aab`, пройти проверку политики.
4. Внутреннее / закрытое тестирование → открытое → production.
5. Привязать приложение в AdMob (тот же package name).

### 6.2. Дополнительные / альтернативные сторы

Имеет смысл, если нужен охват вне Play или дублирование:

- **RuStore**
- **Huawei AppGallery**
- **Samsung Galaxy Store**
- прямая раздача APK (сайт / Telegram) — хуже для доверия и обновлений, реклама сложнее

Для первой версии достаточно **Google Play** (+ при желании RuStore).

## 7. Как рекламировать игру и привлекать игроков

Два разных смысла «рекламы»:

1. **Реклама внутри игры** → ты зарабатываешь (AdMob).
2. **Реклама самой игры** → ты платишь или продвигаешь органикой, чтобы получить установки.

### 7.1. Органика (дешево, обязательно)

- **ASO** (App Store Optimization): название, ключи в описании, иконка, первые скриншоты, короткое видео;
- отзывы и ответы в Play Console;
- короткие вертикальные ролики геймплея (Reels / Shorts / TikTok / VK Клипы);
- посты в профильных чатах/каналах про инди-игры.

### 7.2. Платная реклама (когда игра уже «держит» игрока)

Имеет смысл только если есть удержание и положительная экономика (доход с пользователя > стоимость установки):

- **Google App Campaigns** (UAC);
- **Unity Ads / ironSource / AppLovin** как сети user acquisition;
- VK Ads / другие локальные сети — по аудитории.

Правило для соло: сначала сделать игру и монетизацию, набрать хоть небольшую органику и метрики, **потом** крутить платный трафик маленьким бюджетом.

### 7.3. Модель денег (упрощённо)

```
Установки → сессии → показы рекламы (и/или покупки) → выплата AdMob
→ учёт дохода как самозанятый → налог НПД
```

Комиссии:

- Google Play забирает долю с **покупок в приложении** (не с AdMob напрямую так же);
- доход от AdMob приходит от рекламных сетей;
- у самозанятого — налог с дохода по правилам НПД.

## 9. Риски и ограничения (честно)

- На рекламе с маленьким числом установок доход будет **маленьким** — это нормально для первой игры.
- Без удержания платная закупка пользователей почти всегда в минус.
- Копировать чужой IP (точные клоны брендов) нельзя — механики можно вдохновлять, арт и названия свои.
- Слишком частая interstitial-реклама убивает отзывы и удержание.
- Детская аудитория сильно усложняет рекламу и политики — для старта лучше 12+/16+.
